Defect and correction
---------------------

Every live `POST /topics` reached the server and returned HTTP 503 while
preview remained HTTP 200. PostgreSQL logged SQLSTATE 42501 for `area_groups`.
The application selected the area's mappings with `SELECT ... FOR SHARE`, but
PostgreSQL requires UPDATE privilege for that row-lock mode. The packaged
runtime contract deliberately grants SELECT/INSERT/DELETE and denies UPDATE on
the mapping table.

The correction removes only that redundant mapping-row lock and renames the
generated query to describe the mechanism honestly. Publication already holds
the parent area `FOR SHARE`; area administration takes the conflicting parent
area `FOR UPDATE` before changing mappings. This preserves the existing
serialization and least-privilege contracts without a schema or grant change.
Readiness now positively requires area-group SELECT and continues to reject
area-group UPDATE.
