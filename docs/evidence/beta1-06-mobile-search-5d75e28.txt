Beta.1 narrow-screen search corrective admission
=================================================

Scope
-----

The published annotated tag 1.0.0-beta.1 resolves to
96ac77b2d9fad03bdd528b83a2c0763820ed644c. Its first live accessibility
pass found horizontal overflow on /search at a 320 CSS-pixel viewport: the
date-filter wrapper used an unconditional two-column grid. That tag remains
immutable failed-candidate evidence and is not a known-good reference.

This admission covers only the corrective implementation and its test
methodology. Release identity, guarded merge, package/image reproduction,
application-only replacement, live smoke, and owner confirmation remain the
subsequent 1.0.0-beta.1.1 release gate described by B1-06.

-----------------------

The corrective series:

- changes the date-filter wrapper from unconditional grid-cols-2 to
  sm:grid-cols-2, stacking the controls below the 40rem breakpoint;
- regenerates the Tailwind stylesheet and changes its content-addressed name
  from app-3faf03fa...css to app-3104ce3e...css;
- updates the embed, pinned digest, generator target, and canonical route
  inventory to the exact new stylesheet identity;
- retains and serves the published Beta.1 stylesheet at its original digest so
  its one-year immutable cache contract is not broken;
- serves the stylesheet in the discovery browser fixture; and
- adds a Chromium reflow gate that waits for applied CSS, checks actual client
  width, and directly proves the two date-filter rows stack at 320 CSS pixels.

Negative control
----------------

The final test harness was overlaid onto a clean detached checkout of the
failed release source commit 96ac77b2d9fad03bdd528b83a2c0763820ed644c.
Through Caddy, both the empty base path and /bb failed as required. Chromium
reported the old wrapper class "grid grid-cols-2 gap-3", two 121px columns,
and same-row geometry (fromBottom=682, toTop=612) at the 320 CSS-pixel gate.

Earlier draft oracles were rejected because they passed the known-bad tree:
the fixture did not serve CSS and the width check used innerWidth instead of
the document client width. The admitted negative control includes both repairs
and proves that the gate detects the original defect.

Positive browser control
------------------------

Command:

  GOTTH_BB_BROWSER_CADDY=1 go test -mod=readonly -tags=integration \
    ./internal/httpui -run '^TestDiscoveryBrowserThroughCaddy$' -count=1 -v

Result: PASS on the implementation-equivalent tree for both supported base
paths. The gate loads the exact stylesheet, requires stacked date rows at 320
CSS pixels, and runs the shared 320-pixel and 200%-zoom reflow assertions.

The first cold review correctly observed that changing the shared reflow helper
also affects the abuse-rejection, administration, and unread browser gates.
The complete affected Caddy/Chromium matrix was therefore rerun on final commit
b4c6b8ec7647bda3243c4a398102fa0b94e55483 at both the empty base path and
/bb:

  TestAbuseRejectionNoScriptThroughCaddy
  TestAdministrationKeyboardAndNoScriptThroughCaddy
  TestDiscoveryBrowserThroughCaddy
  TestUnreadControlsKeyboardAndNoScriptThroughCaddy

Result: PASS. Every reflow assertion reported scrollWidth no greater than
clientWidth. Axe reported zero violations; its pre-existing gradient
color-contrast checks remained explicitly incomplete rather than being called
passes. The candidate regenerated without tracked drift before this matrix.
