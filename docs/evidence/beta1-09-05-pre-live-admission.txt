Rejected intermediate work and repairs
--------------------------------------

- The documented loopback rehearsal was initially impossible because the
  control descriptor/client, registration and invitation constructors, and
  SMTP mailer independently reimposed HTTPS after configuration had admitted
  test-only loopback HTTP. The final candidate admits only exact
  `127.0.0.1` or `localhost` HTTP issuers at those internal boundaries;
  production configuration still requires HTTPS.
- Test-mode request admission initially rejected Caddy's forwarded identity.
  The final candidate trusts it only for production or a test-only loopback
  public authority distinct from the numeric listen authority. Direct test
  listeners still reject forwarded identity.
- Authentik grants creator-scoped invitation view only after the creator has
  made its first invitation. The first-page implementation initially called
  remote list and could never create that first object. The final candidate
  trusts only the structurally closed local never-created sentinel, and calls
  remote reconciliation once any local invitation has existed.
- The first five-pass browser run exposed a race where the harness clicked
  newly swapped group pagination before HTMX completed request/swap/settle.
  The final harness waits for those explicit lifecycle classes to clear. Ten
  repair repetitions and five final exact-head repetitions passed.
- The representative fixture predated B1-09 and created its administrator in
  the new fail-closed `unknown` identity state. The repaired fixture models
  accepted actors and suspended identities explicitly.
- The resource harness demanded that PostgreSQL remove every closed backend
  from `pg_stat_activity` in the same instant the client socket closed. Under
  mixed million-row load, one backend could remain briefly visible. The final
  gate polls for at most two seconds and still requires the exact baseline;
  the admitted run returned one to one.
