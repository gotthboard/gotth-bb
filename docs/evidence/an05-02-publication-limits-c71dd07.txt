Results
-------

- Every final exact-tree gate passed. Repository-wide race/coverage passed for
  all packages. Serial and race PostgreSQL integration passed for all packages.
- `internal/abuse` statement coverage was 93.6%; direct coverage for
  `NewPublicationPolicy`, `PublicationPolicy`, `Valid`,
  `RetryAfterSeconds`, and `PublicationReady` was 100%.
  `DecidePublication` was 91.9%; its uncovered statements are defensive
  overflow/impossible-interval guards following already-proven ordering checks,
  not an untested admitted outcome.
- PostgreSQL integration coverage was 94.3% for `internal/forum`, 100% for
  `internal/readiness`, 100% for `migrations`, and 97.1% for `internal/store`.
- Migration 000011 preserved an existing account's `ctid`, installed the exact
  finite-time and tuple constraints, rejected positive/negative infinity,
  zero/negative/100001 counts with a non-NULL start, and a nonzero count with a
  NULL start. Fresh and upgrade migration paths, idempotence, readiness drift,
  and the exact two-column runtime grant were exercised.
- Runtime-role execution proved SELECT plus coherent update/reset of exactly
  `publication_window_started_at` and `publication_count`. Unrelated-column
  update, `created_at` update, user insert, and user delete each failed with
  SQLSTATE 42501. Readiness also rejected a same-name CHECK impostor, default
  drift, and any added UPDATE authority outside the two-column tuple.
- The pure decision matrix covered new/established age boundaries, empty,
  active, expired, clock-regressed, exactly-one-window-ahead and farther-future
  starts, count below/equal/above policy limits, PostgreSQL year one, finite
  minimum/maximum subtraction saturation, bounded whole-second retry, and the
  admitted two-window burst.
- Topic/reply transactions explicitly used read committed, installed 2s
  statement and 250ms lock limits before the account lock, reloaded live role,
  suspension, mute, and groups, authorized the target before counter mutation,
  and committed the counter with the content insert. Every mocked transaction
  stage has failure/rollback evidence.
- PostgreSQL evidence covered all roles, live mute/suspension and a concurrent
  suspension writer, empty and near-limit `2N+2` mixed topic/reply batches,
  separate-account nonserialization, process restart persistence, changed
  configuration against existing state, insert rollback, cancellation, lock
  timeout, and both atomic outcomes for an unknown commit acknowledgement.
- Four deterministic membership cases proved grant and revocation with the
  membership writer first and publication first. Publication observes exactly
  the group set serialized by the user-row lock: a committed prior grant is
  admitted, a committed prior revocation is denied, an in-flight later grant
  cannot retroactively admit, and an in-flight later revocation cannot
  retroactively deny.
- `FOR NO KEY UPDATE` retains publication serialization with every non-key
  account mutation while remaining compatible with foreign-key `KEY SHARE`;
  the focused PostgreSQL case proved this removes the earlier needless lock
  conflict without permitting group drift.
- Edits and previews performed no publication counter work. Denied target,
  malformed actor state, renderer failure, and rate rejection had no target or
  counter side effect.

Non-gate invocation mistakes
----------------------------

- One integration invocation used the wrong variable name
  `GOTTH_TEST_POSTGRES_URL`; tests failed closed because
  `GOTTH_BB_TEST_DATABASE_URL` was absent. The exact command was corrected and
  both serial and race suites passed.
- The first successful race suite was accidentally started a second time while
  its unified execution session was being polled. Both runs completed with
  exit status zero. Only the later single final run is claimed as the gate.
- A remote `make generate` attempt stopped at the pinned Node version check
  because `development` has Node 26.5.1. Deterministic generation was therefore
  performed only on the canonical local Node 26.7.0/npm 12.0.2 environment;
  remote Go vet/tests used the already-attested exact generated tree.
