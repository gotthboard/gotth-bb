Scope and topology
------------------

The candidate packages one Compose project with six long-running services:
stack Caddy, Board, Board PostgreSQL 17, Authentik server, Authentik worker,
and Authentik PostgreSQL 16. Caddy and Board use host networking only for
explicit loopback/public bindings. Authentik and its database use private
networks; Board and Authentik databases use separate durable paths. All four
third-party images are content-pinned. The Board image is immutable by both
release tag and exact local image ID. No service receives the Docker socket.

The direct-host, shared-host edge, and loopback-test tuples are closed by the
packaged preflight. Shared-host mode leaves the existing multi-site TLS Caddy
in place, binds stack Caddy only to the two exact loopback listeners, preserves
the public Host and HTTPS scheme, overwrites caller forwarding headers at the
outer edge, and repeats alternate-header removal at the stack edge.

Cold-review permission correction
---------------------------------

The first cold pass rejected an unjustified Compose override that ran the
Authentik worker as root even though the pinned image declares UID 1000 and
every required writable path is prepared for UID/GID 1000. Commit
`c350339686c6b5c10d5184c49e3ff5bb2dee6311` makes UID/GID 1000 explicit in
the common Authentik service contract, removes the worker's root override, and
adds a regression assertion forbidding `user: root`. The correction changes no
identity, network, enrollment, storage, or user-facing behavior. It resets the
required CLEAN-review counter.
