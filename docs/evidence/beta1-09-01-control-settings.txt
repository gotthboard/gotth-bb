Results
-------

- All final gates passed.
- Migration 000013 is present in deterministic order on fresh and upgrade
  paths. It installs exact closed checks/defaults, backfills active identities
  to accepted and currently suspended identities to removal-required, and
  creates pending-registration, invitation, and email-test state without
  deleting existing rows.
- Runtime cannot select `sessions.token_hash`. Three fixed-shape
  security-definer functions retain indexed credential comparison/revocation
  at the migration-owner boundary, have fixed search paths, deny PUBLIC, and
  are executable by the non-owning runtime role. Runtime JIT insertion can set
  only the explicitly admitted accepted sync-state column in addition to its
  existing profile/time tuple; table-wide user INSERT remains denied.
- Control values are typed and rejected when malformed, non-closed, above a
  startup ceiling, subsecond, inconsistent, or non-SMTP registration is
  requested while SMTP is disabled. No persisted value is silently clamped.
- One settings transaction revalidates and locks the administrator, locks the
  singleton, rejects stale/no-op/overflow revisions, changes the tuple, and
  appends one redacted audit. Audit failure rolls back the settings change.
  Concurrent writers admit one winner and one conflict or bounded lock-timeout
  loser. A committed-but-unacknowledged result is returned as unknown without
  retry, and its exact revision plus audit remain inspectable.
- Publication reads current database limits inside the existing atomic counter
  transaction. The simultaneous-change fixture pauses after the old settings
  statement without holding a database lock, commits a new policy, proves the
  in-flight request uses the coherent old snapshot, and proves the next request
  observes the new policy. The immutable request limiter and destination
  matcher are unchanged.
- Session authentication reads idle/revalidation policy in the indexed active
  session statement. A tightened idle value rejects the next protected
  request, while maximum age and cookie expiry remain startup-only ceilings.
- Maintenance is evaluated after session resolution. Ordinary visitor/member/
  moderator/administrator traffic receives a private no-store 503 with fixed
  Retry-After; current-administrator recovery plus login, callback,
  revalidation, logout, setup, static, liveness, and readiness boundaries
  remain reachable. Settings-read failure also fails ordinary traffic closed.

Rejected intermediate work
--------------------------

- The first integration compile compared a generated row containing a slice.
  That is invalid Go and irrelevant to the contract; the assertion now checks
  the required `pgx.ErrNoRows` result.
- The first simultaneous-policy fixture held a user row while trying to beat
  the production 250 ms lock timeout. Under host scheduling pressure the test
  correctly timed out. It was replaced with a statement-boundary pause that
  proves old/new policy ordering without weakening or racing the timeout.
- The first upgrade suspension fixture let PostgreSQL evaluate `created_at`
  after `suspended_at`, violating the existing timestamp check by microseconds.
  The fixture now supplies an earlier explicit creation/update/login tuple.
- Privilege review found the JIT SQL wrote accepted sync state without the
  corresponding narrow INSERT grant. The exact column grant and a real
  restricted-role JIT insertion test were added before commit.
- Runtime-grant reset initially covered tables and sequences but not prior
  direct function grants. The complete contract now revokes all direct
  function grants before restoring only the three admitted session functions,
  and readiness rejects function ownership by runtime.
